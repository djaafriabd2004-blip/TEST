========================================================================
  دليل تثبيت ورفع البوت على منصات الاستضافة (Railway / Heroku / Render / VPS)
========================================================================

البوت مجهز بالكامل للرفع والتشغيل على جميع أنواع الاستضافات دون الحاجة لأي تعديل في الكود. يرجى اتباع التعليمات أدناه لرفع وتنصيب البوت بنجاح.

------------------------------------------------------------------------
  القسم 1: الرفع والتشغيل على الاستضافات السحابية (Railway / Heroku)
------------------------------------------------------------------------
المنصات السحابية مثل Railway تقوم بتشغيل البوت تلقائيا عند ربطها بمستودع GitHub الخاص بك.

الخطوة 1: رفع ملفات البوت الى GitHub
1. قم بانشاء حساب على موقع GitHub (اذا لم يكن لديك حساب).
2. انشئ مستودعا جديدا (New Repository) واجعله "خاصا" (Private) لحماية ملفاتك.
3. قم بفك ضغط ملف البوت ورفع كافة محتويات المجلد الى المستودع الخاص بك على GitHub.
   (تاكد من رفع ملفات: bot.py, Procfile, railway.json, requirements.txt وجميع المجلدات).

الخطوة 2: ربط المستودع بالاستضافة (مثال: منصة Railway)
1. سجل الدخول الى موقع Railway.app واربط حسابك بحساب GitHub.
2. اضغط على "New Project" ثم اختر "Deploy from GitHub repo".
3. اختر المستودع الخاص بالبوت الذي قمت برفعه في الخطوة السابقة.

الخطوة 3: ادخال مفاتيح التشغيل (Environment Variables)
بما ان الاستضافة السحابية لا تقرا ملفات ال .env المحلية مباشرة، يجب عليك ادخال الاعدادات في لوحة التحكم:
1. في مشروعك على Railway، اذهب الى تبويب "Variables".
2. قم باضافة المتغيرات التالية بدقة (اضغط Add لعمل متغير جديد):
   * BOT_TOKEN : (ضع هنا توكن البوت المرخص لك)
   * LICENSE_KEY : (ضع هنا كود الترخيص الرقمي المستلم من المطور)
   * LICENSE_EXPIRY : (ضع هنا تاريخ انتهاء الترخيص المستلم، مثلاً: never)
   * BINANCE_API_KEY : (ضع هنا مفتاح بايننس العام الخاص بك)
   * BINANCE_SECRET_KEY : (ضع هنا مفتاح بايننس السري الخاص بك)
   * DB_NAME : store.db
   * PORT : 8080 (او اترك المنصة تحدده تلقائيا)
3. بمجرد اضافة المتغيرات، ستقوم منصة Railway باعادة بناء البوت وتشغيله تلقائيا في الخلفية.

ملاحظة: البوت مجهز بملف تشغيل تلقائي سحابي (Procfile) وملف اعدادات سحابية (railway.json)، لذلك ستقوم الاستضافة بالتعرف على امر التشغيل وبناء البيئة تلقائيا دون اي تدخل منك.

------------------------------------------------------------------------
  القسم 2: اعداد التخزين الدائم (مهم جدا!)
------------------------------------------------------------------------
تحذير: الاستضافات السحابية مثل Railway تمسح جميع الملفات المؤقتة
(بما فيها قاعدة البيانات store.db) عند كل اعادة نشر او اعادة تشغيل!
لذلك يجب عليك اعداد تخزين دائم (Volume) لحفظ بيانات المستخدمين والمعاملات.

اعداد التخزين الدائم على منصة Railway:
1. اذهب الى مشروعك على Railway.app
2. اضغط على الخدمة (Service) الخاصة بالبوت.
3. اذهب الى تبويب "Settings" (الاعدادات).
4. انزل الى قسم "Volumes" واضغط على "Add Volume" او "+ Mount Volume".
5. في خانة "Mount Path" اكتب المسار التالي بالضبط:
   /app/data
6. اضغط "Add" او "Save" لحفظ التخزين الدائم.
7. الان اذهب الى تبويب "Variables" وقم بتعديل متغير قاعدة البيانات:
   DB_NAME : /app/data/store.db
   (بدلا من store.db فقط)
8. ستقوم Railway باعادة تشغيل البوت تلقائيا. من الان فصاعدا، جميع
   بيانات المستخدمين، الارصدة، المعاملات، والمنتجات محفوظة بشكل دائم
   ولن تفقد عند اعادة النشر او التحديث.

اعداد التخزين الدائم على منصة Render:
1. اذهب الى Dashboard الخاص بخدمتك.
2. اضغط على "Disks" في القائمة الجانبية.
3. اضغط "Add Disk" وحدد:
   * Name: bot-data
   * Mount Path: /app/data
   * Size: 1 GB (او حسب حاجتك)
4. عدل متغير DB_NAME ليصبح: /app/data/store.db

اعداد التخزين الدائم على منصة Heroku:
منصة Heroku لا تدعم التخزين الدائم للملفات المحلية.
ينصح باستخدام Railway او Render او VPS بدلا منها.

ملاحظة مهمة: على الخوادم الخاصة (VPS)، التخزين دائم تلقائيا
لان ملفاتك محفوظة على القرص الصلب للسيرفر ولا تحذف عند اعادة التشغيل.
لذلك لا تحتاج لاي اعداد اضافي على VPS.

------------------------------------------------------------------------
  القسم 3: الرفع والتشغيل على الخوادم الخاصة (VPS - Linux / Ubuntu)
------------------------------------------------------------------------
اذا كنت تمتلك سيرفر خاص (VPS) وتريد تشغيل البوت عليه، اتبع هذه الخطوات عبر ال Terminal:

الخطوة 1: رفع الملفات للسيرفر
قم برفع مجلد البوت بالكامل الى السيرفر الخاص بك باستخدام برامج نقل الملفات مثل (SFTP / FileZilla).

الخطوة 2: تحديث السيرفر وتثبيت بايثون
شغل الاوامر التالية لتحديث الحزم وتثبيت بايثون:
sudo apt update
sudo apt install python3 python3-pip python3-venv -y

الخطوة 3: تهيئة ملف الاعدادات
افتح ملف .env في مجلد البوت وقم بملء البيانات الخاصة بك (التوكن، معرف الادمن، مفاتيح الترخيص المستلمة، ومفاتيح بايننس).

الخطوة 4: انشاء بيئة عمل افتراضية وتثبيت المكتبات
1. انتقل لمجلد البوت في السيرفر:
   cd path/to/bot-folder
2. انشئ بيئة العمل الافتراضية:
   python3 -m venv venv
3. قم بتفعيل بيئة العمل:
   source venv/bin/activate
4. ثبت المكتبات المطلوبة:
   pip install -r requirements.txt

الخطوة 5: تشغيل البوت في الخلفية (بحيث لا يتوقف عند اغلاق النافذة)
لتشغيل البوت بشكل دائم في الخلفية، يفضل استخدام اداة screen او systemd.
مثال باستخدام screen:
1. افتح نافذة جديدة:
   screen -S telegram-bot
2. شغل البوت:
    python3 run.py
3. للخروج من النافذة وابقاء البوت يعمل: اضغط على الاختصار (Ctrl + A ثم Ctrl + D).

------------------------------------------------------------------------
  القسم 4: التشغيل السهل والمضمون عبر Docker (مستحسن جداً)
------------------------------------------------------------------------
التشغيل باستخدام Docker يضمن عمل البوت المجمع ثنائياً (.so) على أي نظام تشغيل (Ubuntu, CentOS, Debian, Windows) دون القلق بشأن تثبيت بايثون أو إصدارات المكتبات يدوياً.

المتطلبات: يجب أن يكون برنامج Docker مثبتاً على السيرفر.

خطوات التشغيل:
1. افتح نافذة الأوامر (Terminal) في مجلد البوت (dist).
2. قم ببناء صورة البوت (Image) محلياً:
   docker build -t telegram-bot .
3. قم بتشغيل الحاوية (Container) في الخلفية بشكل دائم:
   docker run -d \
     --name my-bot \
     --restart always \
     -p 8080:8080 \
     -v $(pwd)/store.db:/app/store.db \
     --env-file .env \
     telegram-bot

سيعمل البوت مباشرة في الخلفية وسيرتبط التخزين لقاعدة البيانات بشكل دائم.
لرؤية السجلات الحية للبوت:
   docker logs -f my-bot

------------------------------------------------------------------------
  القسم 5: اعداد واستخدام REST API للموزعين (Reseller API)
------------------------------------------------------------------------
البوت يوفر واجهة API جاهزة تتيح للموزعين (Resellers) شراء المنتجات
وعرضها برمجيا. اليك طريقة الاعداد:

كيف تجد رابط ال API الخاص بك؟
الرابط يعتمد على نوع الاستضافة التي تستخدمها:

1. على منصة Railway:
   بعد نشر البوت بنجاح، اذهب الى مشروعك على Railway واضغط على الخدمة.
   ستجد رابط المشروع العام (Public Domain) في تبويب "Settings" > "Networking".
   اذا لم يكن موجودا، اضغط "Generate Domain" لتوليد رابط.
   سيكون الرابط بهذا الشكل:
   https://your-project-name.up.railway.app

2. على منصة Render:
   بعد نشر البوت، ستجد الرابط في لوحة تحكم الخدمة تحت "URL".
   سيكون بهذا الشكل:
   https://your-service-name.onrender.com

3. على سيرفر خاص (VPS):
   استخدم عنوان IP الخاص بسيرفرك مع المنفذ (PORT):
   http://YOUR_SERVER_IP:8080

نقاط ال API المتوفرة (Endpoints):
   GET  /api/health              - التحقق من حالة السيرفر
   GET  /api/me                  - عرض بيانات المستخدم
   GET  /api/products            - عرض جميع المنتجات المتوفرة
   GET  /api/products/{id}       - عرض تفاصيل منتج معين
   POST /api/buy                 - شراء منتج

طريقة المصادقة (Authentication):
كل طلب API يجب ان يحتوي على مفتاح API في الهيدر:
   X-API-Key: YOUR_API_KEY_HERE

كيف يحصل الموزع على مفتاح API؟
1. يقوم الموزع بالتسجيل في البوت عبر تليجرام.
2. يقوم الادمن بتفعيل مفتاح API للموزع من لوحة تحكم الادمن في البوت.
3. يتم ارسال مفتاح API تلقائيا للموزع عبر البوت.

مثال على طلب API (باستخدام curl):
   curl -H "X-API-Key: abc123" https://your-project.up.railway.app/api/products
